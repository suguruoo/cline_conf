# レポート規則と lint ルール ID の対応

`lint_report.py` が検査するもの (ID) と、検査できないもの (人間/アノテーションチェック) を分けて示す。

## 構造・形式

| 規則 | 具体 | lint |
|---|---|---|
| GitHub Markdown | GFM の構文のみ使用 | STRUCT-0 (未閉じフェンス・未記入プレースホルダ) |
| テンプレ | 先頭 `# ■ 題`、次に `レポート作成日時:`、`レポート指示プロンプト:`、以降 `## ● …`、最後 `## ● 参考資料` | STRUCT-1〜4 |
| 作成日時 | `date` の出力。形式 `YYYY-MM-DD HH:MM [TZ]`、未来日付は不可 | DATE-1 |
| 指示プロンプト | 依頼文を原文のまま。この範囲は和英スペース・絵文字検査の対象外 | STRUCT-2 |
| 不確実性 | 見出しに「不確実」「限界」「留意」を含む `## ●` が 1 つ以上 | PRINCIPLE-1 |

## 引用と参考資料

| 規則 | 具体 | lint |
|---|---|---|
| 引用記法 | 本文の出典は `[1]`、複数は `[1][2]`。`[n]` の前後は半角スペース 1 つ (行頭・行末を除く)。`。` `、` の前後も同様 | CITE-1 |
| 対応 | 本文の `[n]` は参考資料に定義があり、参考資料の `[n]` は本文で使われている | CITE-2, CITE-3 |
| 参考資料の書式 | 下記 3 行 1 組。番号は 1 からの連番 | REF-1〜5 |
| 原文引用 | 該当箇所のみ (目安 1,500 文字以内)。省略は `…` か `[...]` で区切る | REF-4, QUOTE-1 |
| 引用が実在 | 台帳のスナップショット (スクリプトが取得した本文) に、空白を無視して一致する | QUOTE-1 |
| 台帳 | 参考資料の URL が全て台帳に登録済み | LEDGER-1 |

参考資料の書式:

````
[1] ページタイトル - サイト名
https://example.com/page
```
原文のまま
```
````

## 一次/二次の明記

- 台帳の `tier` と `origin` で判定する。
- 一次ソースを含む `[n]`、または互いに独立した (origin が異なる) 複数ソースを並べた `[n][m]` は、マーカー不要。
- **単一の二次ソースだけ** に基づく記述は、直後に `（二次）` を付ける: `…とされる [3]（二次） 。` (TIER-1)。
- 一次ソースに `（二次）` を付けると警告 (TIER-2)。未検証ソースを使う文には「未検証」と書く (SRC-1)。

## 表

- 表の **直下** (空行は可、他の文は不可) に ` ```json table N ` (N は 1 からの連番)。
- JSON は行オブジェクトの配列: `[{"列名": "値", ...}, ...]`。キーは表のヘッダ、値は表のセルと一致 (装飾 `**` や `[n]` は無視して比較)。
- lint: TABLE-1〜3。

````
| 項目 | 内容 |
|---|---|
| A | 値 [1] |

```json table 1
[
  {"項目": "A", "内容": "値 [1]"}
]
```
````

## 図・画像

- 抽象概念・アーキテクチャ・プロセスは図で説明する (lint では検出できない。アノテーションチェックで確認)。
- 記号 (`+ - | _` や罫線) で描いた図は禁止 (DIAG-1)。
- 簡易な図は ` ```mermaid ` (mmdc で構文検証。MERMAID-1)。複雑な図は draw.io で作り、`図.drawio.svg` に書き出して `![説明](図.drawio.svg)` で貼る
  (`.drawio` を直接参照するのは不可: IMG-3)。
- Web 検索で得た画像は `![説明](https://…)` で参照してよい (ローカル保存は不要)。**直下の行に出典 `[n]`** を付ける (IMG-2)。到達不能な URL はエラー (URL-1)。

## 絵文字

- 使ってよいのは許可リスト 14 種: ✅ ❌ ⚠ 💡 📌 📊 🔍 📝 🔧 🚀 🔒 💰 ⏱ 🧩 (`scripts/config.json` で管理。上限 15 種)。
- 見出しの装飾に使いすぎない。意味を持たせる箇所 (注意、結論、不足など) に限る。 (EMOJI-1, EMOJI-2)

## 和英スペース

- 日本語 (ひらがな・カタカナ・漢字) と英数字が隣接する箇所には半角スペースを 1 つ入れる (SPACE-1)。
  - 良い例: `やっぱり b がいいです。` / `Web 検索` / `10 件`
  - `（）、。` の隣は不要: `やはり、b がいいです。` / `hogehoge。AWS では`
- 検査対象外: コードブロック内、URL・リンク先、HTML タグ、レポート指示プロンプトの範囲。インラインコードは英語として扱う (前後に空ける)。

## 自動検査できないもの (アノテーションチェックで確認)

事実の正確性、日本語表現の自然さ、結論が証拠に対して妥当か、図が必要な箇所に図があるか、
依頼の想定と異なる点の明記、反証探索の結果の記載。
