# アノテーションチェック

目的: 書いた本人の思い込みを除き、レポートの正確性・日本語・結論の妥当性を検証する。
lint を通した **後** に実施し、結果を `tasks/<id>/annotations.md` に記録する。本文には混ぜない。

## 実施方法

1. レポートを **最初から読み直す** (執筆時のメモに頼らない)。観点ごとに別のパスで行う。
2. 各観点で見つけた指摘を `annotations.md` に書く。指摘が無い観点は『指摘なし』と書く (空は不可)。
3. high / medium は修正して `状態: resolved` にする。修正したら lint を再実行する。
4. 修正しない場合は `状態: wontfix` と `理由:` を書く (high/medium の wontfix は result 承認時に人間が判断する)。
5. 必要なら `use_subagents` で、読み取り専用の突き合わせ (引用とスナップショット、数値の再確認) を並列に依頼してよい。
   サブエージェントは Web 検索・ファイル編集ができないので、結果は自分が `annotations.md` に転記する。

## 3 観点

### 1. 情報の正確性
- 本文の各主張が、付けた `[n]` の原文引用・スナップショットで実際に支持されているか (言い換えで意味が変わっていないか)。
- 数値・日付・固有名詞・バージョンが原文と一致しているか。古い情報を現在の事実として書いていないか。
- 一次/二次の区分は妥当か。二次ソースの孫引きを一次扱いしていないか。
- 反証探索の結果が書かれているか。見つからなかったことも記載されているか。

### 2. 使用した日本語表現の正確性
- 誤字・脱字・文法の誤り、文体の不統一 (です・ます / だ・である)。
- 断定の強さが根拠に見合っているか (「必ず」「明らかに」「〜に違いない」)。
- 用語の統一 (同じ概念に複数の呼び名を使っていないか)。曖昧な指示語。
- 和英スペース・引用記法は lint で検査済みなので、ここでは自然さを見る。

### 3. 帰結の妥当性
- 結論は、本文で示した証拠から導けるか。飛躍・過剰な一般化・相関と因果の混同がないか。
- 依頼文の期待に合わせて結論を丸めていないか。依頼の想定と異なる点が明記されているか。
- 不確実性・限界・未検証事項が結論の近くに書かれているか。
- 抽象概念やアーキテクチャの説明に、必要な図があるか。

## annotations.md の書式

```markdown
# Annotations: <題>

## 正確性
- [A-001] 重大度: high | 状態: resolved | 箇所: ## ● 本論 3 段落目 | 根拠: [2] の原文は 2024 年の数値 | 修正案: 年を明記し [4] を追加
## 日本語表現
指摘なし
## 帰結の妥当性
- [A-002] 重大度: medium | 状態: open | 箇所: 要約 | 根拠: 「優位」と断定しているが証拠は 1 件 | 修正案: 「優位とみられる (確度: 中)」
```

- 指摘 ID は `A-001` から連番。`重大度` は high / medium / low、`状態` は open / resolved / wontfix。
- gate は、high/medium が open のまま、観点の欠落、書式の誤りを FAIL にする。
