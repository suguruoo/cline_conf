# 🔍 ウェブ検索・リサーチルール

## 🎯 このルールが起動する条件

以下のキーワードを含むリクエストで起動します：

- 「〜を探してきて」「〜を調べて」「〜をリサーチして」
- 「〜を検索して」「〜の最新情報」「〜について教えて」
- 「〜の事例」「〜のベストプラクティス」「〜のドキュメント」
- 「〜はどうやるの？」「〜とは何か？」（技術的な質問）

---

## 📋 ワークフロー

### STEP 1：リサーチトピックの確認・精緻化

リクエストを受けたら、推論したトピックを確認する：

```
「〇〇についてリサーチします。このクエリで進めますか？」
選択肢：[「はい、進めてください」 / 「クエリを絞り込みたい」]
```

「絞り込みたい」の場合：
- より具体的な観点（技術スタック・バージョン・ユースケース）を確認する
- 絞り込んだクエリを提示して再確認する

---

### STEP 2：リサーチ深度の選択

タスクの性質に応じて深度を選択する（または自動判断する）：

| 深度 | 用途 | 手法 |
|---|---|---|
| 🔎 **クイック検索** | 仕様確認・エラーメッセージ調査・事実確認 | Web検索 × 1〜2件 |
| 📖 **標準リサーチ** | 技術選定・実装方法・ベストプラクティス調査 | Web検索 + ページ取得 × 3〜5件 |
| 🔬 **ディープリサーチ** | 競合比較・アーキテクチャ調査・未知領域の探索 | 複数ソース横断 + 要約 |

---

### STEP 3：情報ソースの優先順位

以下の優先順位で情報を収集する：

**一次情報（最優先）**
1. 公式ドキュメント（`docs.xxx.com`、`docs.python.org` 等）
2. GitHubリポジトリ（README・CHANGELOG・Issues）
3. 公式ブログ・リリースノート

**二次情報（技術コミュニティ）**
4. 日本語技術記事：Zenn → Qiita → はてなブックマーク
5. 英語技術記事：Stack Overflow → dev.to → Medium
6. 論文・技術レポート（arXiv等）

**注意事項**
- 情報の**日付を必ず確認**する（1年以上前の情報は注意書きを付ける）
- 複数ソースで**裏付け**を取る（1ソースのみの情報は「要確認」と明記）
- AIが生成したコンテンツを一次情報として扱わない

---

### STEP 4：アウトプット形式の選択

```
「結果をどの形式で提供しますか？」
選択肢：
  1. チャットで要約（手軽に確認したい場合）
  2. Markdownファイルに保存（`research/[トピック名].md`）
  3. 構造化データ（比較表・リスト形式）
```

ファイル保存を選んだ場合：デフォルトファイル名は `research/[YYYY-MM-DD]-[トピック名].md`

---

### STEP 5：リサーチ実行

収集した情報を以下の構造で整理する：

```markdown
## 🔍 リサーチ結果：[トピック名]
実施日：[日付]

### TL;DR（要約）
- 核心的な答え1文
- 重要なポイント 3〜5個

### 詳細

#### [サブトピック1]
...情報...
ソース：[URL]（[日付]確認）

#### [サブトピック2]
...

### ⚠️ 注意・未確認事項
- [要確認の情報]
- [古い可能性のある情報]

### 📎 参照リンク
- [タイトル](URL) - [情報の概要]
```

---

### STEP 6：完了

```
<thinking>
リサーチ完了前チェック：
□ リサーチトピックはユーザーの意図と一致しているか？
□ 一次情報（公式ドキュメント）を確認したか？
□ 情報の日付を確認し、古い情報に注意書きを付けたか？
□ 複数ソースで裏付けが取れているか？
□ 「要確認」事項を明示したか？
□ アウトプット形式はユーザーの希望通りか？
</thinking>
```

## 🌐 検索クエリ最適化のガイドライン

### 効果的なクエリ作成

```
# 曖昧なクエリ → 具体的なクエリへ
❌ 「Python 非同期」
✅ 「Python asyncio FastAPI 非同期処理 2024 ベストプラクティス」

# 日本語と英語を使い分ける
日本語：国内事例・Qiita/Zennの知見・日本語ドキュメント
英語  ：公式ドキュメント・GitHub Issues・Stack Overflow
```

### バージョン・日付の扱い

- ライブラリ/フレームワークの情報はバージョンを明示する
- 「最新」「現在」という表現は使わず、実際のバージョン番号を使う
- 情報が1年以上前の場合は ⚠️ を付ける
