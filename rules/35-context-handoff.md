# コンテキスト監視と引き継ぎ (必須)

コンテキストが溢れると、判断の根拠や承認状況を失う。状態は常にファイルに出し、段階的に引き継ぐ。

- **常時**: ステップを 1 つ終えるたびに `progress.md` を更新する (後でまとめて書かない)。会話ではなくファイルが正。
- **監視**: 環境情報などでコンテキスト使用量が見える場合は毎ターン確認する。見えない場合は hook の通知 (`[harness] コンテキスト推定 …`) に従う。
  hook は推定使用率を積算し、段階ごとに指示を出す (既定: 50% 警告 / 65% 引き継ぎ開始 / 80% 強制)。
- **50% (警告)**: 区切りの良いところまで進め、`progress.md` を最新にする。大きなファイルは範囲指定で読み、長い出力はファイルに保存して必要な部分だけ読む。
- **65% (引き継ぎ開始)**: 新しい作業を始めない。着手中のステップだけ終え、`taskctl handoff` で `handoff.md` を作り、
  『引き継ぎメモ』(直近の判断と理由 / 未解決の問い・懸念 / 次の一手 / 注意) を具体的に記入する。`taskctl handoff --check` が PASS になったら、
  `new_task` ツール (使えなければユーザーに `/newtask` を依頼) で新規タスクへ引き継ぐ。
- **80% (強制)**: hook が引き継ぎ作業以外を拒否する。引き継ぎ手順だけを行う。
- **圧縮が起きたとき** (PreCompact): `handoff.auto.md` と `progress.md` を読み直して状態を復元し、区切りで引き継ぎを作る。
- **新しいタスクの開始時**: アクティブなタスクがあれば、最初に `handoff.md` (無ければ `handoff.auto.md`) と `progress.md` を読み、`/tasks.md` の手順で再開する。
  coding のタスクなら `profile-coding` skill を読み込み直す。承認や判断を、記憶ではなくファイルで確認する。
- 引き継ぎメモに書くのは、次の担当 (自分自身) が判断を誤らないための情報だけ。経緯の物語は不要。
